# RUHI Browser — Release Checklist

## Before beta
- [ ] App name and application ID finalized.
- [ ] Version name/code set.
- [ ] App icon, adaptive icon, and splash/launch experience checked.
- [ ] App label consistently says RUHI Browser.
- [ ] No placeholder or fake feature presented as functional.
- [ ] Build/test report reviewed.
- [ ] Crash and error paths tested.
- [ ] Privacy policy URL prepared and accessible.
- [ ] Data collection and sharing accurately documented.
- [ ] All permissions justified and explained.
- [ ] Third-party licenses and filter-list licenses reviewed.
- [ ] AI/VPN disabled unless real integrations are configured and tested.
- [ ] Incognito limitations explained clearly.

## Before Google Play submission
- [ ] Build a signed Android App Bundle (AAB) using local secure signing setup.
- [ ] Do not share keystore passwords or private signing keys in chat or source control.
- [ ] Verify target SDK and current Google Play requirements.
- [ ] Complete Data safety form truthfully.
- [ ] Complete content rating and app access details.
- [ ] Add store listing text and screenshots.
- [ ] Test release build, not just debug build.
- [ ] Confirm no debug logs, test endpoints, or hardcoded secrets remain.
- [ ] Keep a backup of source code and signing material in secure storage.
